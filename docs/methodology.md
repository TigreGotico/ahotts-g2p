# Methodology

How this port is produced and how its correctness is established.

## How the port was written

`ahotts-g2p` is an **AI-assisted, human-guided, test-driven** port -- "vibe
coded" in the open sense: the implementation was generated by an AI coding
assistant working against a behavioural target, under human direction.

- An **AI assistant read the public AhoTTS C/C++ source** and reimplemented the
  linguistic algorithms (normalization, grapheme-to-phoneme, syllabification,
  lexical stress, dictionary decode) in plain Python.
- A **human guided** the work: choosing targets, reviewing output, and accepting
  or rejecting changes based on measured parity.
- The **humans never read the upstream C source themselves.** They steered and
  judged the port entirely through its behaviour against the AhoTTS binaries.

Because the implementing AI read the GPL source, this is a **source-derived**
port, not a clean-room one, and it is licensed GPL-3.0 to match upstream. See
[licensing.md](licensing.md).

## The binaries are the source of truth

Correctness is defined as **behavioural parity with the real AhoTTS binaries**,
not as resemblance to the source. Each engine version maps to a specific binary
(see [versions.md](versions.md)):

- **V1** -- the pyAhoTTS `libhtts` build (`transcribe_text`).
- **V2** -- the modern `ahotts_common` flat-stress path (ahoNT / hitz
  `ahotts/tts`).
- **V3** -- the arrandi `modulo1y2` binary with the 2025 dictionary.

Where a binary provably diverges from its own public source, the port reproduces
the **binary** (the runtime ground truth) and that divergence is recorded.

## Parity verification

Two complementary checks back every claimed number.

1. **Oracle test (exact, in CI).** The official **HiTZ/StyleTTS2-eu** test split
   ships as input/gold pairs under [`../tests/data/`](../tests/data). Every line
   is a parametrized case in [`tests/test_oracle.py`](../tests/test_oracle.py),
   with a guard that fails if exact-match parity ever drops below 25/25. This is
   the contract that the V3 Basque path reproduces the StyleTTS2-eu distribution
   verbatim.

2. **Held-out corpus parity (per version, per language).** Each version's output
   is compared word-for-word against its corresponding binary over a held-out
   corpus. The per-version numbers in [accuracy.md](accuracy.md) come from this
   comparison. Parity is measured against the binary's emitted phonemes, so it
   reflects real engine behaviour rather than a hand-maintained expectation list.

Parity is **not** achieved by memorising the oracle: first-syllable stress
(`STR_MRK`), the no-palatalisation rule (`SALBTF_*`), and the other
dictionary-driven behaviours are read from the **decoded dictionary bitfields**,
and number/date expansion is computed. Only a small set of out-of-vocabulary
foreign-word romanisation quirks that the dictionary does not encode remain as
explicit per-word handling; native vocabulary generalises from the decoded data.

## Reproducing the numbers

The oracle test runs with no external binaries:

```bash
pip install -e .[test]
pytest tests/test_oracle.py -q
```

Reproducing the held-out per-version corpus parity additionally requires the
corresponding AhoTTS binary for each version (V1 `libhtts`, V2 `ahotts/tts`,
V3 `modulo1y2`), since those binaries are the oracle. See
[versions.md](versions.md) for which binary each version maps to.
